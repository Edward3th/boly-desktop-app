Integrate your game
with BolyIntegra tu juego
con Boly

Two kinds of game, two tracks below. A downloadable Windows game adds the Boly SDK and proves it works before you send us a build. A browser-style game (Unity WebGL, Godot HTML5, a plain web build) skips all of that — just export, zip and upload. Tick each step as you go; your progress is saved in this browser.

Dos tipos de juego, dos vías abajo. Un juego de Windows descargable agrega el SDK de Boly y comprueba que funciona antes de enviarnos un build. Un juego tipo navegador (Unity WebGL, Godot HTML5, un build web plano) se salta todo eso: solo exporta, comprime y sube. Marca cada paso a medida que avanzas; tu progreso se guarda en este navegador.

What are you building?¿Qué tipo de juego es?

A browser-style game runs inside the Boly app's own player — no SDK, no verifier. If your export makes an index.html, you're on the right track.
Un juego tipo navegador corre dentro del reproductor propio de la app de Boly: sin SDK, sin verificador. Si tu export genera un index.html, esta es tu vía.

What we sent youLo que te enviamos

  • This guide (the folder you received).
  • Esta guía (la carpeta que recibiste).
  • The Boly SDK for your engine, in the sdk/ folder — it handles the license session for you.
  • El SDK de Boly para tu motor, en la carpeta sdk/: se encarga de la sesión de licencia por ti.
  • boly-verify-win.exe — the verifier that tests your build (run it from this folder).
  • boly-verify-win.exe: el verificador que prueba tu build (ejecútalo desde esta carpeta).

What you needLo que necesitas

  • Just your engine's HTML5/WebGL export — nothing from this kit gets added to your project.
  • Solo el export HTML5/WebGL de tu motor — no agregas nada de este kit a tu proyecto.
  • No Boly SDK and no verifier: Boly's own player controls playback, so there's nothing to integrate or test on your side.
  • Sin SDK de Boly y sin verificador: el reproductor de Boly controla la reproducción, así que no hay nada que integrar ni probar de tu lado.
1

Add the Boly SDKAgrega el SDK de Boly

Copy one folder into your project — nothing to place in a sceneCopia una carpeta a tu proyecto: no hay que colocar nada en una escena

Copy the folder sdk/unity/cl.boly.sdk into your project's Packages/ folder (next to Assets/), so you end up with Packages/cl.boly.sdk/package.json. Unity picks it up on its own — it appears in the Package Manager as Boly SDK and adds a Boly menu. Requires Unity 2021.3 or newer.

Copia la carpeta sdk/unity/cl.boly.sdk dentro de la carpeta Packages/ de tu proyecto (junto a Assets/), para que quede Packages/cl.boly.sdk/package.json. Unity la detecta sola: aparece en el Package Manager como Boly SDK y agrega un menú Boly. Requiere Unity 2021.3 o superior.

Copy the folder sdk/godot/addons/boly_sdk into your project as res://addons/boly_sdk. Then open Project ▸ Project Settings ▸ Plugins and enable Boly SDK — that registers the Boly autoload. Requires Godot 4.

Copia la carpeta sdk/godot/addons/boly_sdk a tu proyecto como res://addons/boly_sdk. Luego abre Proyecto ▸ Configuración del proyecto ▸ Plugins y activa Boly SDK: eso registra el autoload Boly. Requiere Godot 4.

Copy the folder sdk/unreal/BolySDK into YourProject/Plugins/BolySDK, right-click your .uproject ▸ Generate Visual Studio project files, and build. The plugin is a GameInstance subsystem that creates itself — nothing to place in a level. Requires Unreal 5. A Blueprint-only project must become a C++ project first (Tools ▸ New C++ Class, any class) so the plugin can compile.

Copia la carpeta sdk/unreal/BolySDK a TuProyecto/Plugins/BolySDK, haz clic derecho en tu .uproject ▸ Generate Visual Studio project files y compila. El plugin es un subsystem de GameInstance que se crea solo: no hay que colocar nada en un nivel. Requiere Unreal 5. Un proyecto solo-Blueprint debe pasar a C++ primero (Tools ▸ New C++ Class, cualquier clase) para que el plugin compile.

GameMaker has no package import here, so it's three pastes (files in sdk/gamemaker/):

  1. Create a Script named boly_sdk and paste scripts/boly_sdk.gml.
  2. Create an object obj_boly with Persistent checked. Add a Create event with objects/obj_boly/Create_0.gml and an Async ▸ HTTP event with objects/obj_boly/Other_62.gml.
  3. Place one obj_boly instance in your first room (top of the Room Manager).

En GameMaker no hay importación de paquete, así que son tres pegados (archivos en sdk/gamemaker/):

  1. Crea un Script llamado boly_sdk y pega scripts/boly_sdk.gml.
  2. Crea un objeto obj_boly con Persistent activado. Agrega un evento Create con objects/obj_boly/Create_0.gml y un evento Async ▸ HTTP con objects/obj_boly/Other_62.gml.
  3. Coloca una instancia de obj_boly en tu primera room (arriba del todo en el Room Manager).

Requires a 2024+ runtime.

Requiere un runtime 2024 o superior.

💡
The SDK already implements the whole contract — reads the launch arguments, keeps the session alive every ~60 s even while paused, quits if the session is revoked, tolerates a shaky connection. Don't edit its files; everything you need is in Step 2. There is no game id to set either: the launcher passes it at runtime (-game_id). El SDK ya implementa todo el contrato: lee los argumentos de inicio, mantiene la sesión viva cada ~60 s incluso en pausa, cierra si la sesión es revocada y tolera una conexión inestable. No edites sus archivos; lo que necesitas está en el Paso 2. Tampoco hay que configurar un id de juego: el launcher lo entrega al arrancar (-game_id).

Start gameplay when Boly is readyEmpieza el juego cuando Boly esté listo

A few lines in your own code — no bootstrap scene neededUnas pocas líneas en tu propio código: no hace falta una escena de arranque

The SDK validates the session in the background as the game opens. Start gameplay once it's ready, and save progress when the session ends (the SDK closes the game right after that).

El SDK valida la sesión en segundo plano mientras el juego abre. Empieza el gameplay cuando esté lista, y guarda el progreso cuando la sesión termine (el SDK cierra el juego justo después).

using Boly; void Awake() { if (BolySDK.IsReady) StartGame(); else BolySDK.OnReady += StartGame; BolySDK.OnSessionEnded += reason => SaveProgress(); }

Prefer a separate loading scene? Menu Boly ▸ Settings ▸ Scene On Ready loads a scene (Build Settings index) when the session is ready.

¿Prefieres una escena de carga aparte? Menú Boly ▸ Settings ▸ Scene On Ready carga una escena (índice de Build Settings) cuando la sesión está lista.

func _ready(): if Boly.is_ready: _start_game() else: Boly.session_ready.connect(_start_game) Boly.session_ended.connect(func(_reason): _save_progress())

Prefer a separate loading scene? Project Settings ▸ boly ▸ scene_on_ready changes to that scene when the session is ready.

¿Prefieres una escena de carga aparte? Configuración del proyecto ▸ boly ▸ scene_on_ready cambia a esa escena cuando la sesión está lista.

#include "BolySubsystem.h" UBolySubsystem* Boly = GetGameInstance()->GetSubsystem<UBolySubsystem>(); if (Boly->IsReady()) StartGame(); else Boly->OnReady.AddDynamic(this, &AMyActor::StartGame); // UFUNCTION() Boly->OnSessionEnded.AddDynamic(this, &AMyActor::SaveProgress); // UFUNCTION() void SaveProgress(EBolyEndReason)

In Blueprint: Get Game Instance Subsystem (Boly Subsystem) ▸ Is Ready / Bind Event to On Ready. Prefer a separate loading map? Project Settings ▸ Plugins ▸ Boly SDK ▸ Level On Ready.

En Blueprint: Get Game Instance Subsystem (Boly Subsystem) ▸ Is Ready / Bind Event to On Ready. ¿Prefieres un mapa de carga aparte? Project Settings ▸ Plugins ▸ Boly SDK ▸ Level On Ready.

boly_on_ready(function() { start_game(); }); boly_on_session_ended(function(_reason) { save_progress(); });

¿Prefieres una room de carga aparte? En el Creation Code de la instancia de obj_boly escribe room_on_ready = rm_main;.

5

Upload your build on the dashboardSube tu build en el panel

Publish it yourself — an admin approves itPublícalo tú mismo — un admin lo aprueba

Once every verifier check passes, log in at boly.cl and go to your Developer Dashboard → Publish a new game. Fill in the game's name, description and price, optionally add a banner image, and attach your zipped Windows build. Press Create game & upload build. This creates your game as a private draft and starts the upload; nothing is public yet. A Boly admin reviews and approves the build — once approved, your game publishes automatically and is playable from the app. Because the heartbeat is already verified, it launches correctly the first time — no more blind back-and-forth. 🎉

Una vez que todas las pruebas del verificador pasen, inicia sesión en boly.cl y ve a tu Panel de Desarrollador → Publicar un nuevo juego. Completa el nombre, la descripción y el precio del juego, agrega una imagen de banner si quieres, y adjunta tu build de Windows en zip. Presiona Crear juego y subir build. Esto crea tu juego como borrador privado y empieza la subida; nada es público todavía. Un admin de Boly revisa y aprueba el build — una vez aprobado, tu juego se publica automáticamente y queda jugable desde la app. 🎉

📦
The build must be a .zip containing your game's .exe — the desktop app extracts it itself, so no installer is needed. The server inspects the zip on upload and auto-rejects it if it can't find an executable inside, so double-check you zipped the build folder and not just the project. El build tiene que ser un .zip que contenga el .exe de tu juego: la app de escritorio lo extrae sola, así que no necesitas instalador. El servidor revisa el zip al subirlo y lo rechaza automáticamente si no encuentra un ejecutable dentro, así que verifica que comprimiste la carpeta del build y no el proyecto.

Do not use PowerShell's Compress-Archive to make the zip. It writes Windows backslashes as the path separator, which the ZIP format does not allow, and the build then unpacks flat — the game cannot find its own files. The server rejects these on upload. Use 7-Zip, or open a terminal inside the build folder and run: No uses Compress-Archive de PowerShell para crear el zip. Escribe las rutas con backslash de Windows, algo que el formato ZIP no permite, y el build se descomprime plano: el juego no encuentra sus propios archivos. El servidor los rechaza al subirlos. Export your buildExporta tu build

Any tool works, as long as it produces an index.htmlSirve cualquier herramienta, mientras genere un index.html

File ▸ Build Settings ▸ WebGL ▸ Switch Platform, then Build to an empty folder. Unity writes its own index.html plus a Build/ folder — you don't touch either. Any compression setting (Brotli, gzip, disabled) works, the app detects it automatically.

File ▸ Build Settings ▸ WebGL ▸ Switch Platform, y luego Build a una carpeta vacía. Unity escribe su propio index.html más una carpeta Build/ — no tocas ninguno de los dos. Cualquier compresión (Brotli, gzip, desactivada) funciona, la app la detecta sola.

Project ▸ Export ▸ Add... ▸ Web, set an export path ending in index.html, then Export Project. Godot writes the index.html plus its .wasm/.pck files alongside it — export everything into its own empty folder.

Project ▸ Export ▸ Add... ▸ Web, define una ruta de exportación que termine en index.html, y luego Export Project. Godot escribe el index.html junto a sus archivos .wasm/.pck — exporta todo a su propia carpeta vacía.

Whatever your toolchain (Vite, a plain static site, anything else), the only requirement is that your build's output folder contains an index.html — at the root or nested a few levels in, either works. If your bundler emits absolute asset paths (Vite does by default, e.g. /assets/app.js), you don't need to change that: Boly's player resolves them on its own.

Sea cual sea tu herramienta (Vite, un sitio estático plano, cualquier otra), el único requisito es que la carpeta de salida contenga un index.html — en la raíz o anidado unos niveles, ambos funcionan. Si tu bundler genera rutas absolutas (Vite lo hace por defecto, ej. /assets/app.js), no hace falta que cambies nada: el reproductor de Boly las resuelve solo.

📁
Zip your build's output folder (e.g. dist/), never your project's root. A Vite/webpack project also has its own index.html at the root, used only by the dev server — it loads raw, uncompiled source files (/src/main.ts) that don't exist once you zip them, so the game would fail to start. If you zip the whole project by mistake, that root file can get picked up instead of your real build's, and the zip balloons with node_modules in it besides. Run your build command first (e.g. npm run build), then zip only what it output. Comprime la carpeta de salida de tu build (ej. dist/), nunca la raíz de tu proyecto. Un proyecto de Vite/webpack también tiene su propio index.html en la raíz, usado solo por el servidor de desarrollo — carga archivos fuente sin compilar (/src/main.ts) que no existen una vez comprimidos, así que el juego no arrancaría. Si comprimes el proyecto completo por error, ese archivo de la raíz puede terminar siendo el elegido en vez del de tu build real, y además el zip se infla con node_modules adentro. Corre tu comando de build primero (ej. npm run build), y comprime solo lo que generó.

Upload your build on the dashboardSube tu build en el panel

Same dashboard, same review — nothing engine-specific from hereMismo panel, misma revisión — nada específico del motor de aquí en adelante

Log in at boly.cl and go to your Developer Dashboard → Publish a new game. Fill in the game's name, description and price, optionally add a banner image, and attach your zipped build. Press Create game & upload build. This creates your game as a private draft and starts the upload; nothing is public yet. The server inspects the zip and rejects it automatically if it finds neither a Windows executable nor an index.html — so a successful upload already confirms your build is structurally sound. A Boly admin reviews and approves it — once approved, your game publishes automatically and is playable from the app. 🎉

Inicia sesión en boly.cl y ve a tu Panel de Desarrollador → Publicar un nuevo juego. Completa el nombre, la descripción y el precio del juego, agrega una imagen de banner si quieres, y adjunta tu build en zip. Presiona Crear juego y subir build. Esto crea tu juego como borrador privado y empieza la subida; nada es público todavía. El servidor revisa el zip y lo rechaza automáticamente si no encuentra ni un ejecutable de Windows ni un index.html — así que una subida exitosa ya confirma que tu build está bien formado.
